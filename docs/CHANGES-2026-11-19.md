# Release package: branch `feature/share-fix-tenant-tools`

**Base:** `7970ad9` (origin/main, the current Vercel Production deployment). The ZIP snapshot the earlier work started from is identical to that commit; the tree hashes match. Nothing has been pushed, deployed or migrated.

## What changes for customers

### 1. Two calculation defects are fixed (new audits)

**Pro-rata share (`src/services/share-math.ts`).**
- Before: four overlapping checks each added an amount for the same share difference, and each priced it as "statement total × percentage-point gap", which is wrong when that total is the tenant's own charge.
  - Fictional fixture: the statement bills 10.00% against a lease share of 8.08%. The old engine produced four findings and a **$5,086** headline.
  - The statement's own figures give $661,437.20 × 8.08% = $53,444.13, and $66,143.72 − $53,444.13 = **$12,699.59** (shown rounded to $12,700).
- After: one finding. An amount appears only when the statement's figures show the pool the share was applied to: a total line where pool × billed share = the charge, with tolerance set by the precision the share is printed to.
  - If two pools would match, or the share is printed as a whole number, the amount is withheld rather than guessed.
  - An underbilled share is a note and never counts as savings.
  - If the lease's stated share and its square-footage ratio disagree, no expected share is assumed.

**Management fee measured against a total (`computeFeeOverBaseTenantOvercharge`).**
- Before: when the statement did not print the fee rate, the amount was tenant total × excess %. With no tenant total it used the *building* total, which skipped the tenant's share entirely (about 12× too high at an 8% share).
- After: (fee − base × cap%) × tenant share. Fixture: $1,358.75, rounded to $1,359; the old formula gave $1,603. No share means no amount.

New findings carry a structured `checkId` and their `calc` inputs, so later code never has to match on wording.

### 2. Audits already stored are corrected when read

Stored rows are never rewritten. `src/lib/legacy-containment.ts` applies the correction on every read path: audit API and teaser, account list, checkout eligibility, report PDF, dispute letter, and document request.

- Old share findings: the amount is withheld; duplicates collapse into one question that keeps the stored percentages and evidence.
- Old fee-over-base findings: the amount is withheld. The billed share was never stored, so it cannot be recalculated.
- The headline is reconciled by the existing rule. If it does not reconcile, no total is shown.
- Each correction adds its own notice.
- Tested against output from the pre-fix engine itself, and against incomplete and already-correct records. The containment is idempotent and leaves unaffected findings as the same object.

### 3. New features

- **Check the figures used** (paid audits). The tenant can correct a misread number (shares, the share pool, the fee figures, excluded-line amounts).
  - Corrections are stored separately, with the original value and a timestamp, and applied at read time with the same formulas. There is no AI call.
  - The screen, PDF, both letters and the account list all show the corrected view.
  - Items that depend on reading the lease are listed as "not reassessed".
  - Resetting restores the original result exactly.
- **Where to look in your documents** (paid). Every quoted passage, grouped by document and page. The source files cannot be read back from storage (by design), so there is no link or highlighting.
- **CAM cap and base-year calculator** (`/cam-cap-calculator`). Four cap readings plus base year and expense stop.
- **Letter page.** The audit-rights clause is quoted with its stated period. A date is calculated only from a date the tenant enters, with a caution that it is not a legal deadline. A supporting-document request draft is added. Nothing is sent from the page.

### 4. Other changes

- OCR time limits can be configured (`OCR_PAGE_TIMEOUT_MS`, `OCR_TOTAL_TIMEOUT_MS`). The defaults are unchanged: 30 s per page, 90 s in total.

## Rollback assessment

Do **not** roll back by restoring `7970ad9` as if it were a normal revert. That would bring back the double-counted share amounts and the fee formula that skipped the tenant's share, for both new and stored audits.

Safe options, from least to most drastic:

1. **Disable corrections only.** Run the down migration (or skip the up migration). Every audit shows its original result, and the rest of the release keeps working.
2. **Revert individual feature commits** (corrections, source index, letter additions, calculator). Keep commit `9c196ab` (the verified money fixes) and `1a969b4` (consolidated share check and containment).
3. A full revert only with a customer-facing reason to accept the known-wrong amounts.

Stored data written by the new code is compatible with the old code:
- extra JSON fields (`checkId`, `calc`, `auditRights`) are ignored;
- new-wording share findings display as stored;
- `input_overrides` is ignored.

## Internal impact summary (potentially affected paid customers)

**Potentially affected:** paid audits stored before this release whose findings include more than one share finding with an amount, or an "Administrative Fee Cap Exceeded" amount.

**After deploy, those owners will see:**
- a lower or withheld amount;
- a different headline, or "unavailable";
- a notice explaining the change.

**Not established:** how many audits this is, and whether any customer acted on the old figure. Nothing has been inspected.

**Read-only sizing query.** Run only after approval, in the Supabase SQL editor, against the Production project:

```sql
select count(*) as audits,
       count(*) filter (where p.audit_id is not null) as paid
from public.audits a
left join (select distinct audit_id from public.payments where status = 'paid') p on p.audit_id = a.id
where a.status = 'completed'
  and exists (
    select 1 from jsonb_array_elements(coalesce(a.free_findings,'[]'::jsonb) || coalesce(a.paid_findings,'[]'::jsonb)) f
    where (f->>'checkId') is null
      and coalesce((f->>'potential_savings')::numeric, 0) > 0
      and f->>'category' in ('Pro-Rata Share Mismatch','CAM Allocation Discrepancy','Tenant Allocation Discrepancy','Administrative Fee Cap Exceeded'));
```
